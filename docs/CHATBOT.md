# Чат-бот: подключение

## Текущий режим — ссылка

В `js/config.js` укажите:

```js
CHATBOT_URL: 'https://ВАШ-УТВЕРЖДЕННЫЙ-АДРЕС',
```

После этого кнопка на соответствующем этапе скролла станет активной и откроет чат в новой вкладке (`noopener noreferrer`). Пока URL не указан, на странице видно «Скоро здесь можно будет пообщаться», кнопка недоступна. Фальшивая переписка не создаётся.

## Вариант с iframe (после согласования)

Проверьте, разрешает ли провайдер встраивание с помощью `frame-ancestors` CSP / `X-Frame-Options`. Если запрещает, кнопка на внешнюю страницу остаётся корректным вариантом. Для iframe добавьте в чат-карточку компактную оболочку с `<iframe title="Чат с маскотом">`, ленивой загрузкой, адаптивными размерами и заранее разрешёнными origin. Это новая интеграция — сейчас iframe намеренно отсутствует, потому что адрес провайдера не предоставлен.

## API-режим

Если сервис требует API-ключа, в `js/config.js` ключ **никогда не размещать**. Используйте отдельный серверный обработчик, например Vercel Functions / Next.js Route Handler:

1. Браузер делает POST с пользовательским сообщением на **ваш** `/api/chat`.
2. Сервер валидирует длину/формат и выполняет rate limiting.
3. Сервер добавляет API-ключ из server-side переменной окружения и обращается к провайдеру.
4. В ответ возвращает только текст ответа / разрешённые данные.
5. В frontend добавляется штатный чат-компонент с состояниями загрузки/ошибки и обеспечением доступности.

Текущий статический сайт намеренно не содержит вымышленного backend и не выставляет никаких секретов клиенту.
